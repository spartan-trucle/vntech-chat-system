## The decision, as it goes into the text

1. The reply row stores only `reply_to`; no excerpt is copied. The quote is resolved
   from the parent on render, so an edited or deleted parent shows correctly in every
   child: current text, or F10's "message unavailable" placeholder, a render rule.
2. `GET /conversations/{id}/messages` returns a `parents` map beside the page: every
   message referenced by a `reply_to` in the page and not already in it, read by key
   from the store in one batch (bucket from the parent's Snowflake ID). The client
   never issues one request per quote; the device cache keeps parents it has seen.
3. Jump-to-parent (§2.3) is unchanged.
4. Rejected: a denormalized excerpt (stale on edit, survives delete, prebuilds the
   §8.5 follow-up wrong); the client fetching each missing parent (tens of requests
   per reply-heavy scroll).
5. Accepted: a page grows by up to 50 parent rows; a cold-bucket parent adds one keyed
   read; the `msg` handler rejects a `reply_to` from another conversation.
